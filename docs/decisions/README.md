# Decisions — what was decided, dropped or deferred

The decisions index, so a decision buried in a topic file's chronology is visible from one
place and is not proposed again. Two tables with the same columns: **this page holds every
open or rejected decision** — **DEFERRED** with the trigger that reopens it, **DROPPED** with
the rationale — and [01-settled.md](01-settled.md) holds the decisions **DONE** by choice
(architecture, scope, process — down to where the owner's docs procedures stop and the repo's
facts begin, D-41, the machines the gate runs on, D-42, the snapshot's window, D-43, Linux as a build-and-test platform, D-44, the primitive input model, D-25, the cancel and progress path of `Write to File`, D-30, the diagnostics binding, D-37, the publication with a fresh root, D-46, and DualC as a submodule built by CI, D-47) that are not re-litigated. The gate (`decisions-index`) reads
this page: it fails when a `**DEFERRED**` / `**DROPPED**` roadmap entry has no row here, or a
DEFERRED row names no trigger.

One line per row: the ID — `D-NN`, one sequence across both tables, given by decision date
at birth and never reused (the next free number is one more than the largest in the
folder; Boletus's tracked items `#N` are a separate sequence and none is a decision) — the
decision in the present tense, its status, the date it was taken, and the entry that holds
the argument. A trigger marked † was written here after the fact (2026-09-21, roadmap 09
Phase 3), because the record noted the deferral without one; its roadmap entry is not
rewritten. A DEFERRED decision that is dropped keeps its row and its ID, only the status
cell changing; one that lands keeps its ID and its wording and moves to
[01-settled.md](01-settled.md) as DONE, dated the day it landed (D-30, D-37). A decision DualC took for both repositories is cited as `DualC D-NN`,
never restated.
